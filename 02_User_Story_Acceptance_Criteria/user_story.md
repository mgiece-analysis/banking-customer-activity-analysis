# User Story

This document translates the identified business need and requirements into a user-focused perspective.

---

<details>
<summary><strong>1. Main User Story</strong></summary>

> **As a Data Analyst, I want to analyze customer transaction activity across customer, transaction, and branch data, so that I can identify customer activity patterns and prepare reliable information for reporting and further analysis.**

</details>

---

<details>
<summary><strong>2. User Need</strong></summary>

The Data Analyst needs a consistent customer-level view that combines:

- customer information
- transaction activity
- customer type
- regional information
- time-based transaction data

The data should support both detailed customer-level analysis and aggregated reporting.

</details>

---

<details>
<summary><strong>3. Expected User Outcome</strong></summary>

The Data Analyst should be able to:

- analyze customer transaction activity for a selected period
- identify active and inactive customers
- analyze transaction volume and value
- compare customer types and regions
- use the prepared data for reporting and further analysis
- work with a consistent and traceable analytical dataset

</details>

---

<details>
<summary><strong>4. Related Requirements</strong></summary>

The User Story is based on the following requirements defined in the Requirements document:

- Business Requirements: BR-01 to BR-05
- Functional Requirements: FR-01 to FR-10
- Non-Functional Requirements: NFR-01 to NFR-07

</details>
