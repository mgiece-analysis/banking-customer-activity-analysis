# Business Rules

This document defines the business rules used to calculate and interpret customer activity within the Banking Customer Activity Analysis project.

Business rules describe how business concepts and metrics should be interpreted and calculated. They provide a consistent basis for data analysis and reporting.

---

<details>
<summary><strong>1. Analysis Period</strong></summary>

| ID | Business Rule |
|---|---|
| BRL-01 | The default analysis period covers the last three months relative to the latest available transaction date. |
| BRL-02 | The analysis period can be changed when a different reporting period is required. |

The analysis period determines which transactions are included in customer activity calculations.

</details>

---

<details>
<summary><strong>2. Customer Inclusion</strong></summary>

| ID | Business Rule |
|---|---|
| BRL-03 | All customers must be included in the analytical dataset, regardless of whether they have transactions in the selected period. |
| BRL-04 | A customer with no transactions in the selected period remains part of the output but is classified as inactive. |

This rule ensures that the analytical dataset represents the full customer population rather than only customers with recent activity.

</details>

---

<details>
<summary><strong>3. Transaction Count</strong></summary>

| ID | Business Rule |
|---|---|
| BRL-05 | Transaction count is calculated as the number of valid transactions associated with a customer within the selected analysis period. |
| BRL-06 | Customers with no valid transactions in the selected period have a transaction count of 0. |

Only transactions that can be correctly associated with a customer are included in customer-level activity metrics.

</details>

---

<details>
<summary><strong>4. Total Transaction Amount</strong></summary>

| ID | Business Rule |
|---|---|
| BRL-07 | Total transaction amount is calculated as the sum of valid transaction amounts associated with a customer within the selected period. |
| BRL-08 | Customers with no transactions in the selected period have a total transaction amount of 0. |

The total reflects the transaction value generated by each customer during the selected period.

</details>

---

<details>
<summary><strong>5. Average Transaction Amount</strong></summary>

| ID | Business Rule |
|---|---|
| BRL-09 | Average transaction amount is calculated as total transaction amount divided by the number of valid transactions for the customer. |
| BRL-10 | The average transaction amount is NULL when the customer has no transactions in the selected period. |

The average is based only on valid transactions included in the selected analysis period.

</details>

---

<details>
<summary><strong>6. Last Transaction Date</strong></summary>

| ID | Business Rule |
|---|---|
| BRL-11 | Last transaction date is the latest valid transaction date associated with the customer within the selected period. |
| BRL-12 | The last transaction date is NULL when the customer has no transactions in the selected period. |

</details>

---

<details>
<summary><strong>7. Customer Activity Status</strong></summary>

| ID | Business Rule |
|---|---|
| BRL-13 | A customer is classified as Active when they have at least 3 valid transactions within the selected analysis period. |
| BRL-14 | A customer with fewer than 3 valid transactions is classified as Inactive. |
| BRL-15 | A customer with no transactions in the selected period is classified as Inactive. |

The activity status is determined at customer level and applies to the selected analysis period.

</details>

---

<details>
<summary><strong>8. Customer Type</strong></summary>

| ID | Business Rule |
|---|---|
| BRL-16 | A missing customer type is represented as `Unknown` in the analytical output. |
| BRL-17 | Missing customer type values should not exclude a customer from the analytical dataset. |

The `Unknown` category makes missing classification information visible while preserving the customer record.

</details>

---

<details>
<summary><strong>9. Customer Identification</strong></summary>

| ID | Business Rule |
|---|---|
| BRL-18 | A transaction must contain a valid customer identifier to be assigned to a customer-level analytical record. |
| BRL-19 | Transactions with a missing or invalid customer identifier cannot be assigned to a customer and must be treated as a data quality issue. |

Unassigned transactions should not be incorrectly allocated to another customer.

</details>

---

<details>
<summary><strong>10. Duplicate Transactions</strong></summary>

| ID | Business Rule |
|---|---|
| BRL-20 | Confirmed duplicate transactions must not be counted more than once in customer activity metrics. |
| BRL-21 | Potential duplicates must be investigated before being removed from analytical calculations. |

Duplicate handling should be based on available transaction identifiers and defined data quality checks.

</details>

---

<details>
<summary><strong>11. Metric Consistency</strong></summary>

| ID | Business Rule |
|---|---|
| BRL-22 | Transaction count, total amount, average amount, and last transaction date must be calculated using the same selected analysis period. |
| BRL-23 | Customer activity status must be calculated using the same transaction population as the customer activity metrics. |

This ensures that customer-level metrics remain consistent and comparable.

</details>
